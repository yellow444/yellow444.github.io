Генерация рабочей календарной таблицы с помощью WorkingCalendar

Зачем нужен производственный календарь

В повседневной работе многих компаний важно учитывать рабочие и выходные дни — от расчёта зарплат до планирования маркетинговых акций. В типичных корпоративных приложениях часто требуется высчитывать количество рабочих дней между датами, учитывать короткие недели и переносы праздников. Удобно хранить такую информацию в отдельной таблице базы данных.

Репозиторий WorkingCalendar предлагает готовое решение для PostgreSQL, MySQL и MS SQL Server, а на сайте workingcalendar.ru можно сгенерировать SQL-скрипт буквально в пару кликов. В таблице WorkingCalendar хранятся даты и флаг, показывающий, рабочий ли это день. Такая таблица пригодится для планирования отпусков, расчёта зарплаты, маркетинга или распределения ресурсов — многие бизнес-процессы зависят от календаря праздников и выходных.

Источники данных и структура проекта

Проект использует официальный XML-календарь из репозитория xmlcalendar/data. Данные за 2013–2023 годы находятся в папке WorkingCalendar.Server/Data и копируются из upstream-репозитория. Когда выходят данные за новые годы, их можно обновить обычной заменой соответствующих папок (страны: ru, kz, by, ua, uz и т.д.). Источник данных — xmlcalendar.ru, соблюдайте их лицензию.

  • WorkingCalendar.Domain — доменная модель и логика определения рабочих/выходных дней. Класс Calendar парсит XML, определяет тип дня (рабочий/выходной/праздник) и генерирует SQL.
  • WorkingCalendar.Application — сервисы приложения. CalendarService содержит метод GetYearSqlAsync, который создаёт SQL-скрипт для указанного года, типа СУБД и числа рабочих дней в неделе. Если передать year=all, сервис склеит скрипты за все доступные годы.
  • WorkingCalendar.Server — API на ASP.NET Core. Контроллер WorkingCalendarController предоставляет метод GetYearWorkingCalendar, принимающий год, тип БД (mssql/mysql/postgresql) и количество рабочих дней; возвращает готовый SQL-текст.
  • workingcalendar.client — фронтенд (React). Сайт workingcalendar.ru даёт выбрать год, тип БД, рабочую неделю (5 или 6 дней) и получить скрипт. Есть переключение темы/языка и просмотр календаря. Для запуска — порт 8080 (Docker/Helm).

Как формируется SQL-скрипт

Ключевая особенность — генерация SQL “на лету”. Метод Calendar.GenerateSql принимает год, тип БД и число рабочих дней, формируя CREATE TABLE и большой INSERT по всем датам года. 

switch (type)
{
  case "mssql":
    builder.Append("CREATE TABLE WorkingCalendar (id bigint IDENTITY NOT NULL, DateDay date NOT NULL, IsWorkingDay bit NOT NULL);");
    break;
  case "mysql":
    builder.Append("CREATE TABLE WorkingCalendar ( id INTEGER PRIMARY KEY AUTO_INCREMENT, DateDay DATE NOT NULL, IsWorkingDay BIT NOT NULL);");
    break;
  case "postgresql":
    builder.Append("CREATE TABLE WorkingCalendar (id SERIAL PRIMARY KEY, DateDay date NOT NULL, IsWorkingDay bit NOT NULL);");
    break;
}

Далее перебираются все даты года, определяется тип дня и формируется единый INSERT INTO WorkingCalendar (DateDay, IsWorkingDay) VALUES .... Для PostgreSQL флаг рабочего дня оборачивается в кавычки ('1'/'0'), для остальных — без кавычек.

Пример для PostgreSQL (2025):

CREATE TABLE WorkingCalendar (
  id SERIAL PRIMARY KEY,
  DateDay date NOT NULL,
  IsWorkingDay bit NOT NULL
);
INSERT INTO WorkingCalendar (DateDay, IsWorkingDay) VALUES
  ('2025-01-01', '0'),
  ('2025-01-02', '0'),
  ('2025-01-03', '0'),
  -- ...
  ('2025-12-31', '1');

При выборе 6-дневной недели логика вычисления меняется, но формат результата остаётся прежним. Скрипт подходит как для первичного создания таблицы, так и для обновления данных в существующей базе.

Использование API и веб-сайта

Получить скрипт можно через API:

GET /WorkingCalendar/GetYearWorkingCalendar?year={год|all}&type={mssql|mysql|postgresql}&days={5|6}
  • year — конкретный год или all для всех доступных лет;
  • type — mssql, mysql или postgresql;
  • days — рабочие дни в неделе: 5 или 6.

Сайт workingcalendar.ru работает аналогично: выбираете параметры — получаете готовый SQL в текстовой области для копирования.

Развёртывание и обновление

Для Kubernetes предусмотрен Helm-чарт: post-install hook создаёт PostgreSQL и запускает Job с SQL из ConfigMap. Для проверки миграций можно использовать вспомогательные скрипты (временная БД + применение изменений). В Docker укажите переменные окружения, например ASPNETCORE_URLS=http://localhost:8080 или ASPNETCORE_HTTP_PORT=8080.

Обновление данных: скачайте свежие XML из XMLCalendar, замените соответствующие папки в WorkingCalendar.Server/Data и перегенерируйте скрипты. Не забывайте указывать источник xmlcalendar.ru и соблюдать их лицензию.

Заключение

WorkingCalendar и сайт workingcalendar.ru предоставляют практичный способ автоматизировать создание и актуализацию производственного календаря в БД. В отличие от “гайдов с советами”, здесь есть полноценный API и генератор SQL для PostgreSQL/MySQL/MSSQL. Выбираете год, СУБД и схему рабочей недели — получаете готовый скрипт для создания и заполнения таблицы. Благодаря официальным данным, поддержке разных СУБД и простой процедуре обновления решение подходит для первичного внедрения и регулярных апдейтов.
